# 家庭电视 UI 规范

适用基线：0.4.11，2026-10-26。本文是后续设计、实现和评审的规范入口；研究草案、生成图和早期原型不能覆盖这里的已确认规则。尺寸表描述当前实现，调整尺寸须同时更新代码、规范和对应截图；产品规则的改变须先取得用户认可。

## 1. 产品与信息结构

原生 Android TV 桌面，围绕遥控器、家庭常用内容与原应用入口组织。首页负责找到和打开内容，播放、会员、观看进度与系统语音沿用原应用。

- 首页首屏底部仅一行四卡，固定顺序：NBA、宝可梦、海绵宝宝、网易爆米花。爆米花只保留一个入口，不恢复综艺或独立大海报影视首页。
- 家庭卡与后续应用行属于同一连续列表，共用尺寸计算、名称布局、焦点和滚动；不能靠隐藏一套视图、显示另一套视图模拟滚动。
- 顶部保留时钟、日期、输入源、最近打开、网络、应用库和设置。可见按钮顺序为输入源 → 最近打开 → 网络 → 应用库 → 设置；无可用输入源时按配置省略，不留空位。
- 最近打开是本地入口记录；“极光观看历史”是独立的真实应用入口。不得把本地点击记录称为观看进度。
- 共用材质、文字层级和交互。各菜单按内容选择结构，不能强制使用相同矩形容器。

## 2. 首页、背景与层级

- 家庭卡面为 16:9 满幅、圆角、名称与原首页白色焦点边框。原应用卡读安装包图标，去除不必要留白、自然延伸边缘底色，不重画品牌、不额外套深色图标框。
- 卡面和全屏背景分开管理，不能直接把同一张卡面放大充当背景。NBA 用 NBA 标志；角色背景须显示对应角色，主体不能被底部卡片挡住。
- 内容卡/应用卡获得焦点时背景清晰；焦点移至顶部控制区时高斯模糊背景，文字和控件保持清晰。回到卡片恢复清晰。快速移动不能显示过期背景。
- 打开菜单后，菜单内是唯一活动焦点。顶栏撤去原焦点背景，首页轻微压暗，首页操作提示隐藏；关闭后还原。
- 应用库需要较大浏览区域，首页列表进一步弱化，避免两层卡片争夺注意力。其它菜单保留首页背景语境。
- “菜单选中不变白底”约束 `LiquidGlassAction`，不等于取消首页卡片的白色焦点边框，也不改写第三方应用或系统页面的焦点样式。

## 3. 玻璃材质与视觉参数

玻璃通过背景透色、局部模糊、边缘折射和方向性细反光表达。禁止白色/灰白色实心焦点填充、粗白圈、鼓起的气泡曲面、固定彩色光斑，以及覆盖整个控件组的大外框。

颜色以下按 Android `#AARRGGBB` 表示，不能当作 CSS `#RRGGBBAA` 使用。

| 项目 | 0.4.11 实现 | 约束 |
| --- | --- | --- |
| 有背景采样的材质底色 | `#7010161F` | 静止、聚焦、按压保持同一底色 |
| 采样未就绪的回退底色 | `#B8151B23` | 仍是深色，不闪白；不是额外的聚焦色 |
| 主文字 | `#FFFFFFFF` | 清晰，不受背景模糊影响 |
| 菜单说明 / 控件状态 / 页脚 | `#BFFFFFFF` / `#BBFFFFFF` / `#A8FFFFFF` | 按信息层级使用，不用透明度掩盖文字裁切 |
| 控件圆角 | 横向导航 22dp，纵向卡片 18dp；图片内框 9dp | 由共用控件统一维护 |
| 边缘描线 | 静止约 0.55dp，聚焦约 0.75dp | 方向性反光，禁止整圈等亮粗描边 |
| 焦点变换 | 缩放 1 → 1.025，Z 抬升 0 → 5dp | 微弱抬升，不通过换白底表达焦点 |
| 按压变换 | 当前缩放值减 0.025 | 按压与聚焦独立，不等同于触发动作 |
| 焦点过渡 / 菜单淡入 | 180ms 减速过渡 / 180ms | 关闭动画或减少动态效果时立即到位 |
| 首页压暗 | `#40050910` 前景 | 菜单关闭还原；应用库另将首页列表 alpha 设为 0.12 |

字体沿用 `UiFont`。标题 23sp，文字导航 17sp，图标/内容名称 14sp，标题旁辅助操作 13sp，说明 12sp，状态/页脚 11sp。控件标签保持单行并在末尾省略；无障碍名称保留完整标题与状态，不能仅依赖图标或颜色解释操作。

## 4. 五菜单布局

菜单位于顶栏下方，右边距 46dp；普通菜单顶部 112dp，应用库 108dp。控件组外层透明，无描边和额外阴影；尺寸随内容决定，不设置一块统一大背景。

| 菜单 | 信息结构 | 当前尺寸与数量规则 | 默认焦点 |
| --- | --- | --- | --- |
| 输入源 | 设备图标、名称；保留真实 HDMI/CEC/厂商路由 | 卡片 132×96dp，每行最多 4 项；容器约 158–590dp 宽，多项换行 | 第一个真实输入源 |
| 最近打开 | 标题旁独立观看历史入口；正文为内容缩略卡 | 卡片 148×122dp，每行最多 4 项；有内容时容器 320–654dp 宽；历史按钮 180×36dp | 第一个最近入口；无内容时标题旁历史入口 |
| 网络 | 当前连接状态；Wi-Fi 与已配置网络应用并排 | 卡片 132×80dp；容器 158 或 302dp 宽 | Wi-Fi 设置 |
| 设置 | 系统/桌面设置两条导航；下方并排编辑操作 | 容器 294dp 宽；导航高 46dp；编辑卡片 128×68dp，可选项换行 | 系统设置 |
| 应用库 | 原应用图片、名称、简短状态；底部操作提示 | 容器 672dp 宽，4 列、最多 2 行可见；卡高 132dp，纵向步长 140dp；继续下移滚动 | 第一项可操作应用 |

普通组内横向间距 12dp，行间距 10dp；应用库每项左右边距各 6dp、上下各 4dp。标题、说明与正文左边对齐。描述或页脚为空时不占位；可选操作未启用时不留空槽。

空间不足时限制滚动区域，保留标题及底部安全区；当前最大宽度受屏宽减 72dp 约束，底部至少留 28dp。不得为了塞下内容整体缩小字阶。设置导航与编辑不能重新合并成四个等权大按钮。

## 5. 遥控器、触摸与窗口状态

| 状态或操作 | 必须保持的行为 |
| --- | --- |
| 静止 / 聚焦 | 材质底色不变；聚焦仅改变边缘、折射与抬升；可操作层内仅一个焦点 |
| 确认键按下 | 进入按压态并记录本控件收到的按下事件；不立即执行导航 |
| 确认键抬起 | 仅对应本控件有效按下、未取消且未完成长按时激活一次 |
| 长按 | 只在支持的项目打开管理操作；释放不能再触发短按；重复 keydown 不重复执行 |
| 弹层刚打开 | 打开菜单的同一次确认键抬起不能穿透激活第一项 |
| 方向键 | 按真实空间关系移动；边界停止，不能跳到弹层背后的首页 |
| 应用库连续上下 | 按最新目标位置计算，在布局完成后兑现最后一次焦点请求；不能被旧异步请求拉回 |
| 返回 | 关闭当前最内层操作；主菜单关闭后恢复原顶栏入口，背景与提示一并还原 |
| HOME | 关闭弹层并回到单行四卡首页，聚焦 NBA；新建和复用 Activity 行为一致 |
| 窗口失焦 / 退出 | 清理按压与长按计时、撤去活动强调、丢弃过期采样；不能在返回后误触 |
| 鼠标 / 触摸 | 首次点击即可执行，不能第一下只获焦；按下先获焦，不破坏遥控器抬起保护 |
| 关闭动画 / 减少动态效果 | 保留焦点、按压和操作含义，取消过渡，不能丢失反馈 |

首页按下进入同列应用行，第一行随整个列表上移；继续下移自然滚出。按上回到家庭行时，列表恢复底部单行四卡并保持同列。各行共用滚动落点与 300ms 动画；只有明确 HOME/冷启动可直接复位。第三方应用返回保留入口焦点。

## 6. 组件职责与改动位置

| 职责 | 代码入口 | 不得混入的职责 |
| --- | --- | --- |
| 菜单结构、锚点、背景弱化、关闭恢复 | `HomeMenu.java`，`Layout` 五种枚举 | 不为所有菜单固定同一宽高 |
| 图标、文字、图片、状态、焦点与激活 | `LiquidGlassAction.java` | 不在每个业务菜单复制按键和焦点实现 |
| 底色、圆角、薄边反光与纹理过渡 | `LiquidGlassDrawable.java` | 不写菜单标题、内容路由 |
| 内容层采样、共享模糊缓存 | `LiquidGlassBackdrop.java` | 不把当前玻璃层递归采进背景 |
| 边缘折射与双线性取样 | `GlassLens.java` | 不用白色叠加模拟折射 |
| 应用网格与管理操作 | `AppLibraryDialog.java` | 继续复用 `LiquidGlassAction`，不另造焦点材质 |
| 首页行与内容路由 | `AppAdapter.java`、`FamilyShelf.java`、`FilmRoutes.java` | 不把家庭行拆成独立页面；不改变原应用播放职责 |
| 背景与素材 | `ArtCatalog.java`、`OriginalIconArt.java`、`FocusBackdrop.java`、`BackdropBlur.java` | 不将卡面与背景合并，不重绘原应用品牌 |

背景采样在独立内容层执行，模糊在后台处理。菜单打开后补采样以覆盖首页背景过渡，滚动或位置改变后按新坐标采样；过期结果不得覆盖新焦点，动画期间不反复执行 CPU 模糊。

当前共同实现是 API 26 可用的 Bitmap/Canvas 缓存路径，没有连续视频背景追踪或专用 AGSL 后端。它是本项目可复用的原生控件，不宣称完整复刻 Apple 专有材质，也不把模拟器效果等同于所有电视的性能。

## 7. 评审与验收清单

以下是后续变更的验收要求，不表示每一组合都已在所有设备通过。

| 维度 | 必测场景 | 验收依据 |
| --- | --- | --- |
| 五菜单结构 | 少量/多项输入源，最近打开有记录/空态，网络一/两个操作，设置默认/可选编辑，应用库多行 | 按内容决定宽高，无空壳大面板，标题和焦点完整可见 |
| 真实视觉 | NBA 暗背景与宝可梦等彩色背景；同一控件静止/聚焦/按压 | 实际截图看透色、文字、薄边；采样像素只能辅助，不能代替视觉评审 |
| 按键与焦点 | 四向边界、首尾、连续跨行、快速反向、短按/长按、打开后的第一次确认 | 唯一焦点、无越界、无穿透、无重复激活、无旧请求抢焦点 |
| 生命周期 | 返回、菜单内 HOME、第三方返回、冷启动、窗口失焦、首次点击 | 按第 5 节恢复位置和状态 |
| 首页回归 | 四列往返、连续三行上下、顶栏模糊、快速背景切换 | 连续运动与实际显示对应，不能只核对静止落点 |
| 动态与兼容 | 动画开启/关闭、减少动态效果、采样未就绪、实际目标电视 | 焦点可识别，无白色闪烁；帧率性能有单独证据才下结论 |
| 系统与内容入口 | 系统设置/Wi-Fi 的实际 resolver，原应用内容页，Home 辅助 | 使用设备实际解析结果；第三方 UI 树不可用时结合截图与前台 Activity |

本地标准入口：`tools/test-local-guard.py`、`tools/dev.py build`、`tools/check-home-menus.py`、`tools/smoke-ui.py`、`tools/smoke-artwork.py`。最后一项依赖家庭素材，仅在家庭开发仓库运行；公开源树没有私人素材。家庭仓库的 `tools/check-glass-lab.py` 只验证独立控件样板，不能代替五菜单验收。

默认在专用 `FamilyTV_UI / emulator-5580` 开发，并通过右侧内置浏览器展示实际模拟器。测试替身仅证明路由与界面，不证明真实 HDMI 信号、播放、会员、网络或实体遥控。具体版本获用户批准后才更新电视；保留兼容差异、备份与回滚。软件注入按键、实体遥控、小爱、重启及待机应分别记录。

## 8. 规范维护与否决方案

- 改 UI 时同一提交更新对应规范、证据和必要的 `AGENTS.md` 规则；新增控件先复用现有组件，再决定是否扩展组件 API。
- 材质参数改在共用组件，菜单结构改在对应布局；修复一个入口时检查其它复用入口，不复制出第二套实现。
- 0.4.10 的统一 800×360 大面板、设置四等分大按钮、粗白圈/气泡玻璃，以及聚焦变白底，均已被后续用户要求取代，不得当作默认方案恢复。
- 研究文档和旧发布记录保留历史，注明被哪一版取代；当前规范、实际源码、实机状态不一致时应明确记录差异，不能用“测试通过”代替用户验收。
- 私有规范与公开 `public/docs/ui-spec.md` 共用以上规则正文；私人截图、设备与发布证据仅放私有附录。公开仓库不带入设备连接、签名、用户活动数据或影视素材。

## V 通话入口（0.4.19）

首页 V 入口可聚焦，点击立即展开并发出媒体提示音。共享页面就绪后接续原头像位置；原生与网页使用同一通话状态。Home/返回收起并保持通话，首页再次确定恢复；挂断/关屏释放。公开源码采用通用 V 标记，个人头像仅在私有构建。原四卡与五菜单规范继续适用。
